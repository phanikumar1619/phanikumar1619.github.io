BusGo: Bus Ticket Booking System

Featured · Backend-heavy

A redBus-style booking site. Passengers search routes, filter buses, pick seats on a live seat map and get an e-ticket. Admins manage buses, schedules and every booking from a separate panel.

What it does

  • Route search with filters and sort
  • Seat map with boarding and dropping points
  • 4-step checkout: seats, passengers, review, ticket
  • My Bookings with cancellation
  • Admin CRUD for buses, schedules and bookings

Security

  • Passwords hashed with scrypt and a per-user salt
  • Session tokens stored only as SHA-256 hashes
  • Role-based middleware for passenger and admin routes
  • Central error handler returning consistent JSON errors

Data model

  • 12 normalised SQLite tables with foreign keys and CHECK constraints
  • Fares copied into each booking, so later price changes never alter an old ticket
  • Seed scripts for cities, buses, seat layouts and schedules

Request flow

client→routes→session + auth middleware→controllers→services→SQLite

The part I’m proudest of

-- one active booking per seat, per bus, per date
CREATE UNIQUE INDEX one_active_booking_per_seat
  ON booking_seats (schedule_id, journey_date, seat_number)
  WHERE is_active = 1;

The seat check and the insert run inside one transaction, and this partial unique index sits underneath as a safety net. If two users hit “Book” on the same seat at the same moment, one booking goes through and the other gets a 409 telling them the seat was just taken.
